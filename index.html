Situation, task, action, result
Situation
The client needed regular business reports from an application whose source schemas changed and whose data came partly from third-party systems. The warehouse held terabytes of data.
Task
Build and maintain the pipelines feeding the warehouse and make sure reports could be trusted. That meant gathering requirements in person with business and application teams, writing the business requirement documentation, and leading the reporting-factory team.
Action
  • Ran requirements sessions and client meetings on-site in Belgium, and visited the site where the client's product is used to understand what the business needed from reporting.

  • Reconciled Redshift reports against application records in DynamoDB to find missing data, and worked with third-party application teams on their schemas and data gaps.
  • Raised fixes and feature requests on the application team's Jira scrum board and took part in agile planning.
Result
  • Daily refreshes ran on a schedule, and about 100,000 records a day were ingested from Kinesis.
  • Reconciliation exposed missing records. I documented pipeline failures caused by upstream application issues and coordinated fixes with those teams.
  • Presented weekly KPI and data-quality reports in Power BI to client stakeholders, and led knowledge transfer to the team with Confluence documentation.

Time-series aggregation for industrial energy-system optimisation

Research project, thesis in progressGerman Aerospace Center (DLR), 2025–present

Tested whether the usual accuracy metric for compressing a year of hourly prices predicts the quality of the optimisation built on it.

In my benchmark the method with the best nRMSE gave the worst storage sizing (r = −0.96). A quantile-based representation I designed cut sizing error to below 2%.

  • Python
  • tsam
  • scikit-learn
  • oemof.solph
  • Pyomo
  • HiGHS
  • TESPy
  • Streamlit
  • pytest
Situation, task, action, result
Situation
Optimising an industrial heating system over 8,760 hours is expensive, so models often use a few representative periods. Quality is usually judged by how closely the compressed series matches the original (nRMSE).
Task
Find out how the choice of aggregation changes technology selection, operating cost and thermal-storage sizing.
Action
  • Compared six aggregation methods, including hierarchical and distance-based clustering, across a 32-configuration sweep against a full-year reference.
  • Evaluated each with nRMSE, RMSE, load-duration curves and residual distributions, then ran the downstream LP/MILP models.
  • Designed a quantile-based representation after seeing where the others failed.
  • Refactored the research code into a tested package (13 modules, CLI, unit tests) and built a Streamlit app for exploring scenarios.
Result
Fit to the original series and downstream decision quality diverged. The best nRMSE gave the worst storage sizing (r = −0.96). The quantile-based representation reduced sizing error from −17% and −30% to below 2%.

Scope: German electricity-price data and one industrial steam system. Thesis in progress.

Physics-informed predictive maintenance

Research projectEXIST-Women venture, University of Oldenburg, 2026–present

A PyTorch model that flags equipment degradation when labelled failures are scarce, plus a monitoring dashboard around it.

A working LSTM-plus-physics model and dashboard, built for scarce-label data.

  • PyTorch
  • LSTM
  • Physics-informed ML
  • Wavelets
  • Python package
  • pytest
  • GitLab CI
Situation, task, action, result
Situation
Faults in power-electronics equipment are costly, but failure labels are rare in 5-minute telemetry. The research dataset has 16,799 producing observations.
Task
Build a model that can run without failure labels, and a dashboard for service and maintenance teams.
Action
  • Version 1 combines an LSTM branch with a physics branch (Arrhenius temperature ageing, Coffin–Manson thermal-cycling fatigue), trained on healthy data only.
  • Explored wavelet features and cross-manufacturer normalisation over JSON, Modbus and cloud interfaces.
  • Structured the code as a tested Python package with CI, and built the dashboard (fleet monitoring, equipment health, warranty tracking and reports).
A co-founder supplied calibrated fault-simulation data and the physics validation. My part was the modelling, data analysis, dashboard and reports.
Result
A running version 1 and dashboard. Next step: evaluation against real field failures.

Movement analysis pipeline for Parkinson’s patient videos

Research projectUniversity of Oldenburg, 2025

Turned raw patient videos into model-ready time series and trained a transformer encoder on them.

An end-to-end pipeline from patient video to a trained transformer encoder.

  • MediaPipe
  • PyTorch
  • Transformer encoder
  • NumPy
  • Python
Situation, task, action, result
Situation
The research group wanted to analyse motor symptoms from movement videos, linked to clinical UPDRS scores.
Task
Produce clean, structured time-series inputs from the videos for a transformer-based model.
Action
  • Extracted 3D landmarks with MediaPipe, with automated checks for missing detections.
  • Engineered IMU-like features (velocity, acceleration, angular velocity) and cut them into 300-step windows with 67% overlap and 12 features, saved as NPZ files.
  • Trained a transformer encoder (3 layers, 6 attention heads) with label smoothing, cosine learning-rate scheduling and early stopping.
Result
The pipeline runs end to end and is reproducible. Results stay unpublished because the data is clinical research data.

  • Python

Situation, task, action, result
Situation
ancp-bids is an open-source Python library for working with brain-imaging datasets in the BIDS standard. The BIDS schema changes between versions, and the library has to follow those changes while staying fast on large datasets.
Task
Keep the library in step with schema changes, improve its memory use and speed, and make sure new functionality is tested before it reaches the main repository.
Action
  • Developed automation scripts in Python to update schema versions based on changes in the BIDS dataset.
  • Implemented enhancements such as functions for storing temporary artifacts and lazy loading to improve memory usage and execution time.
  • Wrote pytest unit tests, including parameterised test cases, to validate new functionality before merging into the main repository.
  • Pushed code daily and reviewed pull requests from other contributors.
  • Evaluated different LLMs on token usage, model size, memory efficiency and compute time to choose the best code assistant to integrate.
Result
  • Schema-version updates automated instead of done by hand.
  • Lower memory use and faster execution through lazy loading and artifact caching.
  • New features covered by tests before merge, and a code assistant chosen on measured criteria.
